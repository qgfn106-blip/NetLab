# 编码 Agent 硬约束

> 最后修改：2026-11-11
> 适用对象：所有对本项目代码做修改的人类或 AI Agent。
> 单一事实来源：`CODE_STANDARDS.md` 是**代码风格与工程规范**的 SSOT；本文件是**Agent 行为硬约束**的 SSOT。
> 冲突处理：本文件与任务说明冲突时，先停下说明冲突点，不得自行取舍；与 `CODE_STANDARDS.md` 冲突时，代码风格以 `CODE_STANDARDS.md` 为准，行为约束以本文件为准。

---

## 0. 开工前必须先做复用调查

1. 先读 `CODE_STANDARDS.md`、`AGENT_GUIDE.md`、`REQUIREMENTS_AND_RULES.md` 的相关条目，以及要改模块的现有实现。
2. 在动手前输出「复用计划」：
   - 复用哪些现有文件/类/函数/注册表/工具（给出 `file:line`）；
   - 若判断必须新增模块、函数、配置或第二套实现，必须写明：现有实现为何无法满足、新增后如何避免形成第二份真相、是否需要用户批准。
3. 没有这份复用计划，不得写代码。

## 1. 禁止另起炉灶 / 平行实现（含测试性并行例外）

1. 已有能力的唯一实现优先复用；不得为同一能力新建第二套算法、第二套元件模型、第二套配置或第二套格式化逻辑。
2. 正式发布路径上，同一能力只允许一个 canonical 实现；需要扩展时，优先扩展已有接口/注册表/基类，而不是复制后另改一份。
3. 禁止复制粘贴产生「第二份真相」。
4. 发现现有代码有重复（例如元件 Stamp、AC/Bode 后端），不要顺手再写一套；先报告问题并给出收敛方案，等用户或负责人批准后再改。
5. **测试性并行实现例外**（唯一允许的并行实现场景）：
   - 允许：在明确隔离、明确标注为「实验性 / 探针（prototype / 第二实现用于验证）」的前提下，做测试性并行实现。
   - 必须同时满足（缺一不可）：
     a. 必须显式标注实验性，与 canonical 实现不混淆（命名 / 目录 / 开关区分，默认关闭）；
     b. 必须给出「最终合并回原始架构」的方案：合并点、迁移步骤、如何替换 canonical、如何回滚；
     c. 不得形成第二份长期真相——合并完成即删除旧实验实现，禁止长期双轨；
     d. 不得进入正式发布路径 / CI 门禁（除非作为离线只读探针）；
     e. 交付时必须回答：「这套并行为什么最终能并入原始架构？合并代价是什么？」
   - 语义：允许「先并行验证、后收敛合并」，禁止「并入后长期留两套」。

## 2. 禁止直接修改共享状态

1. 只能通过公开 API 和锁访问共享状态：Simulation、Scene、Recorder、NetworkContainer、缓存与全局单例都必须使用既有锁与命令接口。
2. 禁止在无锁情况下直接改 Scene / SERVICE / Recorder / 全局缓存；禁止新增隐式全局单例；禁止绕过事务/命令层直接写状态。
3. 涉及状态变更时，必须说明：谁持有锁、何时提交、失败如何回滚。

## 3. 测试与「过测」红线

1. 测试只断言外部可观察行为；禁止为通过测试新增 test-only 生产分支、隐藏开关或伪造路径。
2. 不得弱化断言、不得 skip 失败测试、不得删除功能来让测试变绿。
3. 测试 oracle 必须独立：优先解析解、参考实现或独立数值结果；不得用同一生产实现自证正确性（只能证明接线，不能证明数值正确）。
4. parity / 等价检查的 allowlist、环境开关或例外必须为空或逐条附理由并经用户批准；不得用例外绕过门禁。

## 4. 改动边界

1. 只改任务相关文件；最小改动；不做与任务无关的「顺手重构」；不改变对外行为。
2. 不擅自改架构、依赖、构建方式或全局配置。
3. 不覆盖、不删除、不格式化他人或无关文件；不把其他会话的未提交改动卷进提交。
4. 预计算/缓存/状态类改动必须考虑失败回滚与用户可见语义。

## 5. 交付前自检

1. `git diff` 必须只包含本任务文件；文档任务中出现 `.py/.ts/.js` 意外改动即停止。
2. 列出「新增/修改点 ↔ 复用点」对照表。
3. 必须运行与改动相关的测试并贴命令与结果；未运行就明确写「未运行」，不得声称已跑。
4. 无真实授权、无真实 CI 时标 `PENDING_USER_AUTHORIZATION` / `UNVERIFIED`，不得伪造。

## 6. 输出格式

用三行交付：

- 改了什么（`file:line` + 一句话）
- 跑了什么（命令 + 结果）
- 输出 / 风险（未验证项、需用户确认项）

任何一条硬约束无法满足时，停止并说明，不要「先做再说」。

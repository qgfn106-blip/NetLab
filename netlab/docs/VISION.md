# NetLab 产品愿景（草案）

> 状态：**草案（2026-11-08）**。本文件对应审计 B-1；正式生效前需产品负责人确认，不得把本文件当作已经冻结的商业承诺。

## 1. 为谁

- 需要在本机快速搭建、修改、运行电路与信号流混合模型的工程师、教师和学生。
- 目标不是替代大型 EDA 或通用多物理场平台，而是把“改拓扑 → 跑瞬态 → 看波形 → 比较解析结果”压缩到一次打开桌面应用的闭环。

## 2. 替代什么、不做什么

**替代的局部工作流**：教科书/论文中的小型电路、控制回路、信号流框图、RC/RLC/二极管/受控源示例，以及用于教学和算法验证的快速原型。当前基线支持信号流与电路两种场景，电路求解以 MNA/Newton 为核心，信号流以块运行时为核心；两者共享 `Scene.clock`，但不宣称等价于工业 SPICE。

**明确不做**：

- 不做完整工业 SPICE 的器件模型库、工艺角、寄生提取、版图或混合信号验证签核；
- 不做云端多用户协作、远程作业调度或商业许可管理；
- 不把 PlotKit 的渲染失败当作求解失败，也不以界面截图替代数值证据；
- 不在没有 benchmark 与回归测试的情况下，用 C++/Rust 重写核心求解器。

## 3. 三条可证伪成功判据

1. **数值可复现**
   - 命令：`python -m pytest netlab/tests/benchmarks -q`
   - 预期输出：`7 passed`（退出码 0；含 RC/RLC 解析解、层 B 能量不变量、层 D 收敛阶 xfail 登记、层 F 变异烟雾）。
   - 失败条件：任一条非 passed、退出码非 0、或收敛阶/解析解断言被放宽（`xfail(strict=True)` 必须保持 strict）。
2. **拓扑不静默改写**
   - 命令：`python -m pytest netlab/tests/test_no_silent_topology_rewrite.py -q`
   - 预期输出：`4 passed`（退出码 0）。
   - 失败条件：任一用例失败；或导入代数环 `.netlab` 后磁盘边集合被改写、异常中缺环路径。
3. **性能可测量**
   - 命令：`python tools/bench_sparse_off_vs_auto.py`（390 节点/391 未知量 RC 梯形，预热 5 步、计时 120 步；同进程对 `sparse=off` 与 `sparse=auto` 取 median/mean/p95）。
   - 预期输出：JSON 中 `"passed": true` 且 `ratio_auto_over_off <= 1.25`（2026-11-09 实测 0.9900，off 5.6679 ms / auto 5.6114 ms），退出码 0。
   - 失败条件：`passed: false`（ratio > 1.25）、进程非 0、或报告缺 median/mean/p95 原始值。

## 4. 当前边界

本草案只确立产品方向与验收口径，不改变 `REQUIREMENTS_AND_RULES.md` 中 R01–R32 的需求编号与 D1–D123 的决策效力。若与现有需求冲突，以需求台账为准，并新开决策行记录变更。

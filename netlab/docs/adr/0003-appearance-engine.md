# ADR 0003：主题外观引擎——单一令牌来源 + 浅/深独立色板

- 状态：Accepted（2026-11-07）
- 关联：D75（主题单一来源）、UI_SPEC（UI 唯一实现口径）、[APPEARANCE_ENGINE_DESIGN.md](../APPEARANCE_ENGINE_DESIGN.md)

## 背景
前端主题令牌现存三处（`style.css` 两处 `:root`、`app.ts THEME_TOKENS`、PlotKit `app.css`）且已漂移，违反 D75；画布大量裸 hex 未走主题映射，深色下出现亮斑；深色被反复调亮至弱化文字近主文字亮度。用户要求“深/浅各一整套完全不同颜色、字体清晰、风格统一，沿用 RhineLabUI”。

## 决策
1. **令牌单一来源**：新增 `frontend/theme.tokens.ts` 为唯一源，构建期生成 CSS 变量，`app.ts` 的 `C()`/`THEME_TOKENS` 同源读取；禁止再手写第二份。
2. **浅/深同一设计语言、各自一套独立完整色板**（Q3=A；深色非反色）。
3. **分期**：一期全局外观引擎（A：令牌收敛 + 双色板 + 画布裸色收敛 + 外观设置面板 9 项），二期元素级视图外观（B）。作用域仅 netlab 主壳，PlotKit 视图本期不动（Q1=B）。
4. **可测量验收**：WCAG 对比度脚本（正文≥7、弱≥4.5、边框≥3，深浅都过）、tsc/build/gui/pytest 123 项、关键界面深浅对比页。

## 后果
- 正面：单一来源消除漂移；深浅清晰且风格统一；画布与 DOM 一致；外观可调。
- 代价：`app.ts` 273 处裸 hex 需逐步迁移；新增开发期令牌生成步骤（保持运行时零构建、产物提交）。
- 约束：深色弱化文字设对比度上限（约 ≤7:1），防止再次“调过头”。

# 前端 UI 文本 / 文本框颜色令牌统一（浅色与深色双主题可读）

## Problem Statement

用户在多处界面发现**文字与文本框看不见 / 看不清**，并且反复调整仍未根治（附截图证据）：

- 深色主题「设置」页：每个设置行的**标题文字**（如「外观主题」「动效强度」「性能模式」）与左侧分组标题（「工程设置」「视图与外观」「交互与文档」「诊断」）呈深灰压在深底上，几乎不可读；而其下方的说明文字却是可读的灰色——**同类文字层级用色不一致**。
- 浅色主题：顶部下拉菜单（仿真 / 分析 / 工具）的**菜单项标题**呈浅白压在浅底上，不可读；其说明文字可读。
- 浅色主题：工具/检查器里的次级按钮（「重置」「清空」「添加节点」）与空态标题（「未选择对象」）呈**白字压浅底 / 白底**，不可读。
- 浅色主题：分段控件（「跟随系统 / 浅色 / 深色」）选中项文字同样发白看不清。

共性根因：界面里存在大量**文本前景色与文本框（输入框/下拉/按钮/菜单/面板）背景色**没有走统一的「浅色 + 深色两套」语义令牌，而是零散使用背景类令牌或写死近似色，导致同一元素在某一主题下前景≈背景。以前的对比度处理只覆盖了整体基调与画布，**没有覆盖「所有文本 / 文本框」这一层**，所以问题反复出现。

用户要求：把这些文字与文本框的颜色**全部定位**，做成**浅色、深色各一套的键值对**（可直接调用），并保证文字清晰、与周边 UI 风格一致；**必须以「截图视觉上能看清」作为唯一验收标准**，看不清就继续调，不得提前收工。

## Solution

在既有「外观令牌唯一来源」之上，补齐并强制执行一层**语义化前景/文本令牌 + 文本框背景令牌**，浅色与深色各一套完整键值对；所有渲染文字与文本框的组件（标题、正文、说明、禁用态、菜单项、标签页/分段控件、按钮、输入框、占位符、字段标签、徽标、提示条、浮层）都只允许引用这套令牌，禁止再出现「用背景令牌当文字色」或写死近似色。

验收通过一个**渲染后界面的可视对比度检查 seam**：在真实 WebView 里按「浅色/深色 × 关键界面矩阵」渲染，对每个可见文字节点计算其前景色与真实背景的 WCAG 对比度并断言达标，同时产出截图供**目视确认能看清**；两项都通过才算完成，否则继续调。

## User Stories

1. 作为使用深色主题的用户，我希望设置页每个设置行的标题清晰可读，这样我能快速找到想改的选项。
2. 作为使用深色主题的用户，我希望左侧分组标题（工程设置/视图与外观/交互与文档/诊断）清晰可读，这样我能分辨分组。
3. 作为使用浅色主题的用户，我希望顶部下拉菜单的菜单项标题清晰可读，这样我能选择命令。
4. 作为使用浅色主题的用户，我希望菜单项的说明文字与标题有明显层级但仍清晰。
5. 作为用户，我希望「重置」「清空」「添加节点」这类按钮文字在浅色与深色下都清晰，且与按钮底色对比足够。
6. 作为用户，我希望主按钮（强调色底）的文字在两种主题下都清晰（必要时用前景令牌而非纯白）。
7. 作为用户，我希望危险按钮（删除）在两种主题下文字都清晰可辨。
8. 作为用户，我希望分段控件（跟随系统/浅色/深色）选中与未选中项的文字都能看清，且选中态有明显区分。
9. 作为用户，我希望标签页/页签的激活与未激活文字都可读、可区分。
10. 作为用户，我希望空态标题（如「未选择对象」）与其说明文字在两种主题下都清晰。
11. 作为用户，我希望输入框内的文字与占位符在两种主题下都清晰，输入框边框与背景可辨。
12. 作为用户，我希望表单字段标签、单位、辅助说明文字清晰且层级分明。
13. 作为用户，我希望禁用态文字仍然可辨（区别于可用态，但不至于看不见）。
14. 作为用户，我希望鼠标悬停 / 选中 / 激活态的文字颜色随状态变化但仍达标。
15. 作为用户，我希望提示条（成功/警告/危险/信息）与浮层（tooltip/popover）中的文字清晰。
16. 作为用户，我希望徽标/标签（badge）在两种主题下都清晰。
17. 作为用户，我希望主题切换后所有文字颜色立即正确刷新，不出现残留的旧主题色。
18. 作为用户，我希望画布之外的 UI 文字与画布风格一致，不突兀。
19. 作为用户，我希望「强调色」变化时，所有依赖强调色的文字（按钮、链接、选中项）自动跟着变且仍然清晰。
20. 作为用户，我希望「字体大小/密度」等外观选项调整后，文字仍然清晰、不被裁切。
21. 作为设计/维护者，我希望所有文本与文本框颜色都以「浅/深两套键值对」集中定义，新增组件时直接引用，不再零散写色。
22. 作为维护者，我希望有自动化检查能在提交前发现任何「前景≈背景」的文字，避免同类问题再次回归。
23. 作为维护者，我希望检查报告能精确指出「哪个界面/哪个元素/哪个主题」不达标，便于快速修复。
24. 作为验收者，我希望每轮修复都有浅色/深色截图凭证，并能在视觉上确认文字清晰后才结束任务。

## Implementation Decisions

- **扩充唯一令牌源（双主题）**：在现有「外观令牌唯一来源」中新增一组**文本/前景令牌**与一组**文本框背景令牌**，并保证 LIGHT、DARK 两套**键集完全一致**、一一对应。建议令牌（命名可按现有风格微调，语义固定）：
  - 文本前景：`text-primary`（主文字）、`text-secondary`（次级）、`text-tertiary`（说明）、`text-disabled`（禁用）、`text-heading`（标题/分组标题）、`text-label`（字段/行标签）、`text-menu-item`（菜单项标题）、`text-menu-desc`（菜单项说明）、`text-tab-active` / `text-tab-inactive`、`text-button-primary` / `text-button-secondary` / `text-button-danger`、`text-input` / `text-placeholder`、`text-link`、`text-on-accent`、`text-tooltip`、`text-badge`。
  - 文本框背景：`field-bg` / `field-bg-focus` / `field-border` / `field-border-focus`、`button-bg-primary` / `button-bg-secondary` / `button-bg-danger`、`menu-bg` / `menu-bg-hover`、`panel-bg`、`tab-bg-active` / `tab-bg-inactive`、`segmented-bg` / `segmented-bg-active`、`badge-bg`、`tip-bg` 等（延续已有的 surface 令牌体系，不重复造两套）。
  - 每个「文本令牌」必须与它所在容器的「背景令牌」成对、且在**其主题**下达标（见测试）。
- **禁用错误用法**：全面清理「把背景类令牌（如 paper / paper-2 / paper-3 / panel-bg 等浅色）当作 `color`」以及组件/内联/JS 动态 DOM 里写死近似色的问题；统一改为引用上述文本令牌。画布（canvas）文字如涉及，复用既有画布调色板令牌，不新开体系。
- **组件全覆盖清单**：设置页（分组标题 + 每行标题 + 说明）、顶部菜单/二级菜单项（标题+说明）、工具栏按钮（主/次/危险）、分段控件、页签、空态、输入框与占位符、字段标签与单位、状态栏文字、提示条、浮层、徽标、禁用态、悬停/激活态——逐项绑定语义令牌。
- **状态与主题联动**：`:hover` / `:active` / `:focus` / `[disabled]` / `[aria-selected]` 等状态各显式绑定令牌；主题切换通过 CSS 变量即时生效，DOM 与画布同一令牌源，避免闪烁或残留。
- **强调色/外观选项联动**：强调色与字号/密度变化只改变令牌值或缩放，不破坏文本令牌的对比保证。
- **令牌是纯数据**：维持「单一来源 → 生成 CSS 变量（构建期、产物入库）」的既有机制；生成脚本与对比度检查脚本同步扩展，CI 校验令牌键集浅/深一致、禁止手工第二份色值。

## Testing Decisions

- **什么是好测试**：只测**渲染后的外部行为**——真实 WebView 中每个可见文字节点的「前景色 vs 真实背景色」对比度，以及出现可见性；**不**断言具体色值/具体选择器/具体实现（色值可能微调）。
- **单一测试 seam（首选，且尽量只有一个）**：以「真实渲染后的 DOM + 计算样式」为最高 seam。启动应用（无浏览器端口模式）+ 通过 CDP 驱动，按场景矩阵遍历：
  - 主题 × 界面：{浅色, 深色} × {设置页全部分组、顶部一级/二级菜单、工具栏主/次/危险按钮、检查器空态与选中态、输入框聚焦/占位符、分段控件、页签、提示条、浮层、徽标、禁用态}。
  - 对每个可见文本节点：取其前景色与**有效背景**（向上追溯到最近的非透明背景；若为透明/图片，则从该文字像素区域采样真实背景），计算 WCAG 对比度并断言：主文字 ≥7、次级 ≥4.5、说明/弱化 ≥4.5、禁用 ≥3、大字号 ≥3（阈值沿用并收紧现有规范）。
  - 输出结构化报告：主题/界面/元素/前景/背景/比值/是否达标；任一不达标即失败。
- **令牌层单测**：断言 LIGHT 与 DARK 的令牌键集完全相同；每个文本令牌与其配对背景令牌在其主题下达到阈值（等价于现有对比度检查脚本的扩展，加入文本/文本框令牌）。
- **截图目视门（用户指定的终态标准）**：上述矩阵同时产出浅色/深色截图集；必须**目视确认文字清晰**才可关闭任务。自动化对比度是必要条件，截图目视是最终确认条件；两者缺一不可。
- **被测范围**：整个前端壳层 UI（DOM 文本与文本框）渲染；令牌模块本身。
- **既有先例（prior art）**：沿用现有「令牌级 WCAG 对比度检查脚本」与「CDP 截图管线」与「GUI 冒烟/probe」三者的做法，新增/扩展为「渲染 DOM 文本对比度审计 + 场景截图集」，不引入新的测试框架。

## Out of Scope

- PlotKit 视图内部（用户明确「PlotKit 视图挺正常」），不改其内部颜色。
- 画布上节点/连线的数据可视化配色（已在既有画布令牌层处理，本轮不重做），除非某处画布**文字**证据显示不可读。
- 布局、字体族、字号体系、图标、动效本身的重新设计（仅保证其与文字可读性不冲突）。
- 新增主题（如第三方导入主题）与逐令牌自由编辑器（属后续阶段）。
- 文件路径、具体 CSS 选择器、具体色值清单（实现时决定，避免快速过时）。

## Further Notes

- 本 spec 由 /to-spec 依据用户当前反馈与已有关键证据综合而成，未做额外访谈。
- 触发证据（截图，本轮已核）：① 深色设置页设置行标题/分组标题深字压深底；② 浅色下拉菜单项标题白字压浅底；③ 浅色次级按钮「重置/清空」与「添加节点」白字压浅底；④ 浅色空态标题「未选择对象」白字压浅底；⑤ 浅色分段控件「浅色」选中项发白。
- 建议保留一份「场景 × 主题」的截图基线目录，作为后续任何 UI 改动的可回归视觉证据。
- 完成定义（DoD）：令牌层覆盖全部文本/文本框；全场景自动对比度 0 失败；浅/深截图目视清晰并经用户确认；CI 令牌一致性检查通过。

# 电路模块化：怎么封装、怎么用

> 适配版本：静态 3.20.1（2026-11-06）。配套代码 `netlab/core/compute/circuit_modules.py`、`frontend/app.ts`（模块库 / 模块内部浮窗段，esbuild 编译为 app.js）。

## 0. 先说这次的「节点不存在」

那三条报错不是封装算法的问题，而是**画布选中集里的节点在服务端已经不存在了**：我上一轮跑验收脚本时，直接在你在用的同一个应用进程里造夹具节点又删掉，你的画布还留着这些 id 被选中，一点封装就去查这些 id，服务端当然找不到。

现在做了三层防护：

1. 每次拿到新场景快照，自动把选中集里已经不存在的节点/导线剔掉；
2. 点封装时再过滤一次，全都没了就自动刷新画布并提示「画布已过期…」；
3. 兜底提示改成「选中的节点已不存在（画布可能已过期，或这些节点刚被封装/删除）：… 请刷新画布后重新选择」。

以后如果还看到类似提示，先 `Ctrl+F5` 刷一次页面。

### 0.1 真正让封装坏掉的那条：器件边没跟着进模块（已修）

还有一类报错是「元件 'resistor-9' 无法装配：'b2e6c66398a5'」。它在运行（不是封装）时冒出来，根因是**旧模型的器件本身就是一条连线**（`kind=resistor` / `vsource` …，没有独立的器件节点）：

- 旧封装只把 `kind=wire` 的导线搬进模块，器件边被漏掉；
- 但父场景里器件两端的网络节点已经被搬走了 → 那条器件边悬空 → 一运行就报「无法装配」。

现在的行为：

- 两端都在选中范围内的器件边，**一起搬进模块**（名字、参数、控制端引用都跟着改）；
- 只有一端落在选中范围内的器件边，直接报「元件 X 的两个引脚分在选中范围的两侧」，不会再生成半截坏场景；
- 运行期兜底：万一老工程里已经有悬空器件边，报错会说明「一端接在已不存在的节点上，请删掉这条元件连线重画」，不再是一串 id。

## 1. 封装：三步

1. **选**：在电路场景里框选或点选要打包的器件 + 网络节点（导线不用选，会自动算）。
2. **点**：右键左侧网络列表 → **封装选中节点为模块…**；或「模块与扩展」→「封装选中」。
3. **起名**：确认后，画布上原来那一片电路被一个模块节点替换，与外界的连接处变成端口。

三条硬规则（决定「能不能封装」）：

| 规则 | 原因 |
| --- | --- |
| 至少要有一个器件 | 只选网络节点没有可封装的内容 |
| 只能选器件 + 网络节点 | 导线、传感器等其它节点不能进模块 |
| 器件（含旧模型里「器件就是一条边」的电阻/电源）两端必须都在选择集内 | 只选一半会让元件悬空，装配时报错；现在会直接拒绝并提示 |

边界处理：穿过边框的导线自动变成端口。**同一个外部网络只出一个端口**（比如分压器中点接了两个电阻，以前会生出 `mid` 和 `mid_2` 两个口，现在合并成一个 `mid`）。完全落在模块内部、但你给它打了端口标记的网络，也会同时导出成端口——这样「内部节点」也能从外面探到。

## 2. 端口方向：为什么以前看起来不分输入输出

因为电路模块的默认方向是**双向（电气）**：电气上两个网络接在一起就是同一个网络，不存在「只能流进」的端口，所以默认不区分。

想区分就显式设：

- 右键那个**网络节点** → **设为模块端口**（还没标记时）→ 子菜单选 **输入 / 输出 / 双向**；
- 已经标记过的节点，右键是 **改端口方向**，同样三选一；→ **取消模块端口** 可撤销。

方向的实际作用：模块符号上引脚画左边还是右边、模块内部浮窗和库卡片里的分组显示（输入 / 输出 / 双向）。它**不改变电气行为**，不会阻止你把线连到「输出」上。信号模块（`signal` 模式）才严格按 input/output 走数据流。

节点属性面板里也有同一组选择（双向 / 输入 / 输出），改哪边都行。

## 2.1 连到模块：为什么以前一定要你「指定引脚」

模块符号是**多个端口的集合**，一根导线接上去，后端必须知道它接的是哪个端口——否则内部网络对不上，所以 `source_pin` / `target_pin` 是必填的。

以前报「起点是器件节点 '模块'，必须指定引脚」，是两个前端漏洞叠在一起：

- `createWireBetween()` 只对 `kind === 'device'` 补引脚，把 `kind === 'module'` 漏了 → 从模块符号拖出去的线**一个引脚都没带**；
- 于是后端只能拒绝。

现在：

- 从模块符号上**点端口小圆点**拖线，用的就是你点到的那个引脚（本来就该如此）；
- **只有一个端口的模块**（比如只有一个入线的分压器），直接拖到符号上就行，前后端都会自动用那唯一的端口；
- 多端口模块在「新建连线」对话框里仍然要选引脚——这一步不能省，否则不知道接哪个口。

## 3. 用模块

模块库在右栏 **模块与扩展 → 模块**：

- **实例化**：在画布中心放一个实例节点，之后像普通器件一样连线。
- **打开内部**：打开模块内部浮窗（只读预览，可以拖动/缩放/最小化）。
- **在临时网络中编辑**：把内部结构打开成一个临时网络，改动会回写；**关闭内部网络** 收掉临时网络。
- **另存为副本**：用当前选中重做一个新模块（v2 之类）。

实例是库模板的一份拷贝：改实例上的参数不影响库。

**库文件布局（2026-10-30 起）**：一个模块一个文件，文件名就是模块名——`library/blocks/<模块名>.block`。旧布局 `library/blocks/<十六进制 id>/v1.block` 在下次启动时自动压平成新名字（同名时后来者加 `-<id前6>`）。文件内部仍记着版本号：内容变了版本自动 +1，但磁盘上只保留最新一份，不再有 `v1/v2` 多份文件。

面板上每张卡片现在有 **实例化 / 打开内部 / 改名 / 删除**：

- 改名：名字重复会立刻提示「模块名已存在」，文件跟着改名；
- 删除：会提示「文件会删、画布实例会变缺失」；仍有工程引用时再确认一次才强删。

现在库里只剩你自己的一个模块：

**`twice`**（信号 / 行为模型，`signal` 模式）

- 输入：`in_signal_path`（信号路）、`in_bias_path`（偏置路），都是 voltage
- 输出：`out_amplifier`，voltage
- 内部：一个 `sum` 节点，`in_signal_path × 2.0 + in_bias_path × 0.5` → 输出
- 用途：把「信号×2 加 偏置×0.5」这条最常见的放大器缩放链打成一个积木，多个通道复用。

「结构 / 行为」两种模型的区别：**结构**（structural）表示内部是真实元件 + 导线，仿真时会被摊平成实际电路；**行为**（behavioral）只声明端口和内部的计算图（信号流），不展开成电路元件。

## 4.1 修复什么时候生效（重要）

后端（Python）改动**必须重启应用**才加载；前端（`app.ts` 等 TS 源经 esbuild 构建为 `app.js`，以及 `style.css`）改完重新构建并刷新页面（Ctrl+F5）就生效。

这次涉及的封装修复、库按名字存盘、改名/删除、以及「保存时报需要一个库路径」的修复，**全都在后端**，所以要做到两件事：

1. 先把当前场景存下来（`文件 → 保存`，或调一次 `POST /api/project/export`）；
2. 关掉应用再重新打开（`NetlabHome/netlab/start_desktop.bat`）。

重启后会发生：`library/blocks/` 里旧目录自动压平；模块库面板能看到 `twice`；封装带旧模型电阻/电源的电路不再报「无法装配」。

「工程使用模块引用，需要一个库路径才能打开」这条，是因为桌面版保存时只做了校验没把库路径传下去（`netlab/desktop/bridge.py` 三处 `validate_project(...)`）。现在保存前会用工作目录的 `library/` 校验，缺模块就降级为「引用缺失但可保存」，并在返回里带 `degraded`，不会再弹这个框。

## 5. 常见报错对照

| 提示 | 含义 / 怎么办 |
| --- | --- |
| 选中的节点已不存在（画布可能已过期…） | 选中集里有已删除的节点。刷新页面后重新选 |
| 封装至少要包含一个器件 | 只选了网络节点。把器件一起选进来 |
| 选中的电路没有任何跨边界连接… | 选中的电路和外面没有导线相连，没有端口可分。把边界导线一起选进来，或先给网络加端口标记 |
| 元件 'V…' 无法装配：'<节点 id>' | 源器件有一端落在选择集外。把它的两端都选进来（旧版本封装漏搬器件边，重启后即修） |
| 工程使用模块引用，需要一个库路径才能打开 | 桌面版保存/打开时没把库路径传下去（已修，重启生效）；手动用 API 打开时带上 `library` |
| 导线不能直接连接两个器件引脚，必须经过网络节点 | 画布上的连线规则，不是封装的问题：两个器件引脚之间要插一个网络节点 |

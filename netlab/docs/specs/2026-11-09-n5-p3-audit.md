# N5 P3 复核裁定（2026-11-09，A′ 收窄版）

依据：`docs/NETLAB_NEXT_PHASE_AGENT_PROMPT_2026-11-09.md` N5、严格审计 §3.2 第 3/4 条、§7.4。
撤回范围与既有 P3 编号的边界见 `netlab/docs/specs/2026-11-09-n5-p3-withdrawal-list.md`。

## 逐条证据（严格审计 §7.4 五项）

1. **LTE 估计 + 自适应步长（rtol/atol、accepted/rejected）**：全仓 `netlab/**/*.py`、`tools/**/*.py` 检索 `LTE|local truncation|adaptive_step|自适应步长|variable_step|变步长`，真实实现命中 **0**（`ast.LtE` 是 Python 小于等于 AST 节点，`_dialog_save`/`_dialog_open` 是文件对话框，均非实现证据）。`simulation.py` 仍是固定 `dt` 循环，无 LTE 估计、无误差拒绝/重算。
2. **统一离散语义**：`elements._source_value()` 已对梯形法取步首/步末平均；但 `elements.py` 在 `gear_dt != dt` 时仍静默回退后向欧拉，`netlab/tests/test_solver_integration.py::test_gear2_dt_change_resets_history` 把「退回 BE」写成期望行为，无 warning/异常/审计字段。**未统一、未显式标记。**
3. **真实 KCL 残差**：`solver._true_residual()` 在解处重新盖章计算 F(x*)=Ax*−b(x*)；`tools/bench_solver.py` 的中点 KCL 失配约 1e-18 A。但 `solver.py` 存在重复的 `_true_residual` 定义（第 533/554 行），且没有公开的 KCL 残差契约，**不能签收**。
4. **cond/残差返回**：`last_residual` 存在；全仓无 `cond` 计算/返回，**未实现**。
5. **延迟语义统一**：`auto_delay` 默认 False，`AlgebraicLoopError` 存在；但未见跨方法统一的延迟语义契约与测试，**未签收**。

## 结论

- 严格审计 §3.2/§7.4 语境下的 **P3 数值内核五项均未完成签收**。
- 本句仅适用于该严格审计语境；仓内其他「P3」编号（R36 子阶段、分析旁路 R11/R12/R17/R34、math_accel M1b/Woodbury）不受影响，逐行清单见 `2026-11-09-n5-p3-withdrawal-list.md`。
- 2026-11-09 已修复的是另一缺陷：梯形法首步电容初始电流 i(0+) 不自洽（P3 前实测收敛 1 阶，修复后 1.98–1.99 阶，见 PROGRESS §7.131）。该缺陷不得用于冒充上述五项，也不在本裁定中记作「P3 完成」。
